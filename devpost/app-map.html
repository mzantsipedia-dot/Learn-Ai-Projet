Salary Check: App Map

A one-page guide to how the app is put together and where to look when you want to change something.

What the app is

One phone-friendly web page that answers "Will my money last until my next salary?" You enter your salary, salary date and debit orders, then add purchases as you spend. The status box compares what's left with your spending pace and the days until salary, and turns red when the money won't last.

It's made of a few plain files with no framework. Everything you type is saved in the browser's local storage (a sticky note for this app on that device). Nothing is sent to the internet.

One action, end to end: pressing "Add"

The route through the code

This is the route followed in the guided code tour (no edit was made).

  1. index.html, search id="add-form": the amount box (purchase-amount), category dropdown and Add button. This file only describes the screen; it does no maths.
  2. app.js, search addEventListener("submit": runs when you press Add. parseAmount rejects blank, zero, negative or non-number amounts with a friendly note; state.purchases.push(purchase) adds it; render() redraws everything and calls save().
  3. calc.js, search function summary: works out spent, left, pace per day and what you'll need until salary. The lines that set status = "running-low" are the exact moment the app decides to turn red.
Show the warning rule from calc.js 
const left = salaryAmount - debitTotal(state) - spent;
const pacePerDay = spent / daysGone;
const needed = roundTo50(pacePerDay * Math.max(0, daysLeft));

if (daysLeft <= 0) status = "salary-day";
else if (left < 0) status = "running-low";
else if (spent === 0) status = "no-purchases";
else if (left < needed) status = "running-low";
else status = "on-track";

A practice to reuse

What happened: after slice 3, the automatic checks passed and the agent's browser test said Reset worked. But when it was tried by hand, Reset did nothing. The test had answered the "Are you sure?" pop-up in code, so it never saw that the browser was quietly blocking the pop-up. Testing again by clicking the real buttons confirmed the fix, which moved the question onto the page (reset-confirm in index.html). It's recorded under Revisions in devpost/checklist.md.

Reuse it: when an agent says something "works", ask how it was checked, and still try the real thing yourself the way a user would. The plan made this easy: every slice in the checklist had a plain-language Learner check, so a human try-out was built into each step. On your next project, write down "what I should see when I try it" for each step before building, and treat a hands-on try as part of "done".

Run it again

  • Simplest: double-click index.html to open it in Chrome or Edge.
  • On a phone: once published with GitHub Pages, open the link and tap Add to Home Screen. See README.md.
  • Check the maths: run node --test in the project folder.
